# Phase 8：受控 JavaScript 诊断设计

## 目标与范围

Phase 8 在现有统一网页上下文和多 CDP Session 基础上，为常规 Selector 难以处理的页面提供可审查、需明确确认的 JavaScript 诊断兜底能力。

本阶段完成 `REQUIREMENTS.md` 中的 8.1–8.6，以及属性面板中的临时 DOM 属性编辑：

- 为普通 DOM、同源 iframe、open Shadow Root 和 OOPIF 生成定位代码。
- 使用 Monaco 展示和编辑完整诊断代码。
- 在选中元素所属的准确 CDP Session 中执行代码。
- 执行前展示目标、上下文、完整代码和风险，并要求用户明确确认。
- 区分成功值、`undefined`、不可序列化值、异常、超时和过期上下文。
- 根据本地快照、上下文和 Selector 验证结果给出确定性修复建议。
- 通过同一受控流程临时编辑目标元素属性，成功后刷新快照。

本阶段只实现诊断 JavaScript，不扩展为自动化执行引擎。执行历史、脚本收藏、循环或定时执行、跨元素流程编排、网络拦截、AI 调用和页面数据上传均不在范围内。

## 方案选择

采用主进程预检和一次性执行令牌组成的双阶段流程。

Renderer 首先发送代码、元素 ID 和快照令牌进行预检。主进程解析元素所属 Session，确认快照与上下文仍有效，计算代码摘要，并返回目标信息、风险和一个短时有效的一次性执行令牌。只有在用户查看预检信息并确认后，Renderer 才能使用该令牌执行一次代码。

不采用以下方案：

- Renderer 确认后直接执行：实现较少，但主进程只能信任一个可伪造的确认字段，无法把确认内容和实际执行代码绑定。
- CDP 隔离世界：隔离性更强，但会改变页面全局变量与框架运行时语义，降低诊断价值，并显著增加 iframe 与 OOPIF 的 execution context 管理成本。

“受控”表示明确目标、双阶段确认、准确 Session 路由、快照有效性校验、执行超时、输入和输出限制。任意 JavaScript 仍可能修改页面状态；产品不得将其描述为安全沙箱。

## 执行契约与安全边界

### 预检

预检请求包含：

- 全局命名空间元素 ID。
- 当前拼接快照令牌。
- 完整 JavaScript 代码。
- 生成策略和是否预期修改 DOM 的风险提示。

主进程执行以下检查：

1. 代码非空且 UTF-16 长度不超过 50 KB。
2. 拼接快照令牌与 `BrowserSession` 最近一次快照一致。
3. 元素 ID 可以解析为 Session ID 和本地元素 ID。
4. Session 存在、状态为 active，revision 与快照路由一致。
5. 本地快照注册表仍持有目标元素。

预检成功后创建 60 秒有效的一次性令牌。令牌绑定代码 SHA-256 摘要、元素 ID、快照令牌、Session ID、Session revision 和预期修改标志。令牌只保存在主进程内存中，不写入 Renderer、磁盘或项目数据；Renderer 只得到不透明 ID。代码、目标或快照变化后必须重新预检。

### 执行

执行请求只包含一次性令牌。主进程取出并立即消费令牌，再次检查过期时间、当前 Session 状态和 revision。任何检查失败都返回结构化失败结果，不调用 `Runtime.evaluate`。重复使用、过期、导航后的令牌均被拒绝。

执行器在目标 Session 中读取当前快照建立的 `window.__uiExplorerElements`，将本地元素作为 `$target` 传给异步诊断函数。用户代码作为字符串传入异步函数构造器，避免通过字符串拼接破坏外层执行包装，并为异常堆栈追加稳定的 `sourceURL`。

CDP `Runtime.evaluate` 使用 `awaitPromise: true`、`returnByValue: true` 和 5 秒超时。主进程同时设置有限的命令看门狗，防止连接异常导致 IPC 永久等待；看门狗只负责结束本次 UI 等待，不把未确认的操作重试到其他 Session。

### 输出归一化

页面内包装器将返回值转换为始终可按值传输的摘要：

- `null`、boolean、number 和 string 保留类型；长字符串截断并标记。
- `undefined` 单独报告，不当作缺失响应。
- bigint、symbol 和 function 返回类型与描述。
- DOM 节点返回节点类型、标签、id、class 和短文本摘要。
- 普通对象与数组进行有深度、条目数和总字符数上限的安全遍历。
- 循环引用、访问器抛错和超过限制的位置使用明确占位描述。

结果判别联合包含 `success`、`exception`、`timeout`、`stale-target`、`validation-error` 和 `connection-error`。异常结果保留清理后的错误消息和可用堆栈；不得将无法按值传输误报为无返回值。

## 代码生成

共享纯函数为选中元素生成三类代码草稿：

- DOM 查询：优先复用当前已验证 Selector 的稳定属性与语义，使用 `querySelector` 或 `querySelectorAll`。
- 树遍历：按文本、属性或位置约束遍历元素，并显式处理零匹配和多匹配。
- 上下文穿透：从当前 Session 的 `document` 开始，按同源 iframe 与 open Shadow Root 边界逐层进入。

生成代码必须可编辑，并以返回定位结果或摘要结束。所有动态字符串使用 JSON 字面量编码，不直接拼接引号或 Selector 文本。

OOPIF 不生成虚假的跨域 `contentDocument` 穿透代码。现有全局元素 ID 将执行路由到 OOPIF 所属子 Session，生成代码从该 Session 的 `document` 开始；界面同时显示完整 frame/OOPIF 上下文路径，使代码起点可审查。

`$target` 始终引用快照中的精确目标，可用于比较生成查询的结果或执行局部诊断。属性编辑使用专门生成的草稿，属性名和值均经过 JSON 编码，并在执行前标记为修改 DOM。属性编辑不会绕过 Monaco、预检或确认步骤。

## 确定性诊断建议

建议只消费本地 `ElementSnapshot`、上下文边界、属性稳定性分析和 Selector 验证结果，不调用模型或网络服务。

规则至少覆盖：

- 零匹配：建议刷新快照、核对动态属性，并使用 `$target` 比较实际上下文。
- 多匹配：建议增加已验证的稳定属性、文本或祖先约束。
- 唯一但目标不一致：建议加入目标语义、上下文边界或更具体的层级。
- 动态 id/class：建议忽略低稳定性属性并采用 role、name、aria 或稳定 data 属性。
- iframe/Shadow 边界缺失：建议使用上下文穿透策略。
- OOPIF：说明代码由 CDP Session 路由，不应尝试跨域读取父页面 `contentDocument`。
- 导航、Session 脱离或快照过期：建议刷新快照后重新预检。
- 超时：建议减少全树遍历、缩小查询根或拆分诊断。

建议使用稳定代码和中英文消息键，底层详情单独展示，便于测试和后续扩展。

## UI 与状态管理

右侧面板新增“JS 诊断”折叠区，并随选中元素和快照更新：

- 顶部显示页面标题、URL、元素摘要和 iframe/Shadow/OOPIF 路径。
- 策略切换提供 DOM 查询、树遍历和上下文穿透。
- Monaco 展示并编辑完整 JavaScript。
- 风险区域显示只读诊断或 DOM 修改标记，以及任意脚本可能影响页面的固定警告。
- “准备执行”触发预检；预检成功后显示确认复选框和“执行一次”。
- 编辑代码、切换元素、刷新快照或更换目标后清除预检和确认状态。
- 结果区按状态展示结构化摘要、异常、超时和修复建议。

属性面板增加临时属性编辑入口。用户填写属性名和值后，工作台切换到 JS 诊断区并载入修改草稿；页面不会在此时发生变化。修改成功后自动刷新 DOM 快照，普通只读诊断不强制刷新。

预检、确认、编辑器草稿和最近一次结果保存在诊断组件本地，不写入 Zustand 持久化数据。Store 只暴露预检、执行和刷新动作，避免把派生 UI 状态写入全局状态。

## 组件边界

### Shared

`src/shared/javascriptDiagnostics.ts` 负责：

- 诊断策略、风险、预检和执行结果类型。
- 基于快照和 Selector 的代码草稿生成。
- 确定性修复建议。
- Renderer 与主进程均可使用的输入验证与展示辅助纯函数。

`src/shared/ipc.ts` 只扩展 IPC 契约和通道，不承载令牌状态或 CDP 逻辑。

### Main

`src/main/diagnosticExecution.ts` 负责：

- 预检请求校验、代码摘要和一次性令牌存储。
- 令牌过期、消费和绑定信息校验。
- Runtime 结果归一化与错误分类。

`BrowserSession` 负责：

- 从最近快照路由中解析全局元素 ID。
- 校验目标 Session 和 revision。
- 在准确 Session 中执行包装后的表达式。
- 导航、脱离或断开时使未消费预检失效。

`main.ts` 和 `preload.cts` 只注册并暴露预检、执行两个最小 IPC 方法。主进程将所有来自 Renderer 的值视为不可信输入。

### Renderer

`src/renderer/components/JavaScriptDiagnosticsPanel.tsx` 独立承载 Monaco、策略切换、预检确认和结果展示。`WorkbenchLayout.tsx` 只提供选中元素、Selector、目标和调用动作，避免继续扩大主工作台职责。

中英文文案添加到现有消息表；样式沿用当前面板、编辑器、风险和状态色体系，不引入新的设计系统。

## 失效与并发语义

- 每次预检只对应一次执行；执行按钮在请求进行中禁用。
- 同一组件可以重新预检，但新预检会替换 UI 中的旧令牌。
- 主进程允许多个未过期令牌存在，但每个令牌独立绑定目标和代码；断开连接、选择新顶层目标或 Session revision 改变时全部相关令牌失效。
- 结果到达时，Renderer 只在元素 ID、快照令牌和预检 ID 仍与当前视图一致时展示，避免陈旧结果覆盖新目标。
- 超时后不自动重试。用户必须重新预检并再次确认。

## 测试与验收

行为密集型逻辑使用 RED/GREEN：

- 普通 DOM、同源 iframe、open Shadow 和 OOPIF 的代码生成起点、边界顺序与字符串转义。
- 一次性令牌与代码摘要、元素、快照、Session 和 revision 的绑定。
- 令牌过期、重复执行、代码或目标变化、导航和 Session 脱离的拒绝路径。
- 精确 Session 路由，特别是不同页面或 Session 中本地元素 ID 相同的情况。
- `undefined`、循环对象、DOM 节点、函数、异常、超时和输出截断的结果归一化。
- 属性编辑代码生成、修改风险标记、预检要求和成功后的快照刷新。
- 本地建议规则及其中英文消息映射。

测试夹具覆盖普通 DOM、iframe、Shadow 和 OOPIF 中可稳定定位的目标，以及异常、长结果、循环对象和超时表达式。最终运行 `npm test`、`npm run typecheck` 和 `npm run build`，并使用代表性测试页面人工检查：

1. 四类上下文均能生成并执行定位代码。
2. OOPIF 代码只在所属 Session 生效，不修改父页面或其他 target。
3. 未预检、未确认、令牌过期或代码变化均不能执行。
4. 返回值、`undefined`、不可序列化值、异常和超时均有明确展示。
5. 属性编辑在确认前不修改页面，成功后刷新快照。
6. 运行过程中不调用 AI，也不上传页面数据。

## 风险与约束

- JavaScript 本身能够修改页面、发起网络请求或触发页面逻辑。界面必须持续展示风险，不得用“沙箱”或“无副作用”描述该能力。
- CDP 超时可以终止当前求值，但页面在超时前已发生的副作用无法回滚。
- 快照元素注册表是运行时引用，不可持久化。导航或刷新后必须重新捕获、生成和预检。
- OOPIF 的 Session ID 仅用于当前连接路由，不进入可移植代码或项目资产。
- 输出限制保护 UI 和 IPC，不保证用户代码自身的内存或 CPU 消耗完全可控。
