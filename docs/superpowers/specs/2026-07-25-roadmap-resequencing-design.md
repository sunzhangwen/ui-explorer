# UI Explorer 后续路线图重排设计

## 目标

重新编排 UI Explorer 尚未完成的功能，使后续开发遵循“网页能力先稳定，再扩展桌面与生态”的顺序。项目管理与 Selector 回归验证推迟到 Phase 8 之后，等网页、桌面和 UiPath 数据模型稳定后再定义 `.uiproj`，减少 schema 迁移和跨模块返工。

本次更新以 `REQUIREMENTS.md` 为目标文档。除路线图和里程碑外，还会修正 MVP 范围、功能阶段引用、表格剩余范围和待确认问题，确保全文一致。

## 排序原则

1. 先完成所有后续网页功能共同依赖的捕获可靠性、诊断和上下文能力。
2. OOPIF 多 Session 会改变快照、选择、高亮、验证和导出，因此必须早于高级表格、JS 执行、项目保存和回归验证。
3. 安全的延迟捕获和热键先于进程冻结；冻结实验等桌面目标模型稳定后再做。
4. 标准 HTML 表格作为已完成的独立阶段保留；高级表格能力后续增量实现。
5. 桌面 UIAutomation 稳定后再确定跨平台 Selector 适配边界。
6. UiPath 映射依赖稳定的网页和桌面 Selector 模型。
7. 项目文件必须晚于网页、桌面和 UiPath 模型，使用版本化 schema 承载已稳定的资产类型。
8. AI 只消费本地确定性诊断，并且所有推荐必须经过本地验证。
9. 企业能力依赖本地项目模型和真实用户反馈，最后启动。

## 新阶段划分

### Phase 4：标准 HTML 表格识别与导出（第 9–10 周，已完成）

范围：

- 标准 `<table>` 结构识别。
- `rowspan`、`colspan` 和多级表头规范化。
- 虚拟化数据预览。
- CSV、JSON、Markdown 复制与文件导出。

不包含 Excel、CSS Grid/Flex 伪表格或行列选择；这些能力移至 Phase 7。

### Phase 5：网页可靠性、动态页面与安全瞬态捕获（第 11–13 周）

范围：

- 目标关闭、跳转、刷新后的状态监控和重连。
- 动态 DOM 刷新及尽可能恢复原选择。
- 完善 accessible name、description、disabled、clickable、遮挡和不可见原因。
- 属性过滤与定位价值标记。
- Selector diff、失败原因和确定性修复建议。
- 延迟捕获、倒计时和全局热键。

本阶段不使用 SuspendThread/ResumeThread，也不引入 Native 冻结模块。

### Phase 6：跨域 iframe/OOPIF 多 CDP Session（第 14–17 周）

范围：

- `Target.setAutoAttach` 和多 Session 生命周期。
- frame、target、session 映射。
- 跨域子 frame 的树、捕获、选择和高亮。
- 跨 Session 坐标换算。
- Selector 验证和多匹配高亮。
- Playwright、Selenium、JSON 导出。
- 无法附加、导航失效和 Session 脱离诊断。

该阶段完成后，后续网页功能统一依赖同一套上下文模型。

### Phase 7：高级表格与结构化数据提取（第 18–20 周）

范围：

- 行列选择和导出范围预览。
- Excel `.xlsx` 导出。
- CSS Grid/Flex 伪表格启发式识别。
- 识别置信度与误判诊断。
- iframe、Shadow、OOPIF 内表格的一致提取。
- 大表格性能验证。

伪表格识别失败时必须明确退化，不能将普通布局误报为表格。

### Phase 8：JS 指令生成、受控执行与高级诊断（第 21–22 周）

范围：

- DOM 查询、树遍历、iframe 和 Shadow 穿透代码生成。
- Monaco 编辑与预览。
- 在正确 CDP Session 中受控执行。
- 执行前展示目标、代码和风险。
- 返回值、异常和超时展示。
- 基于本地 DOM、上下文和验证结果的确定性修复建议。

AI 不进入本阶段。

### Phase 9：桌面 UIAutomation 探索版与冻结实验（第 23–27 周）

范围：

- 评估并确定 .NET sidecar、Rust sidecar 或 Node Native Addon。
- 定义通用目标、快照、属性和 Selector 适配接口。
- 窗口选择、UIA 树、属性展示和桌面高亮。
- UIA 定位描述生成。
- 验证 Win32、WPF、WinUI/UWP；Electron、Qt、Java 作为扩展样例。
- 在桌面模型稳定后实验进程冻结。
- 权限提示、30 秒自动解冻和异常恢复。

冻结不作为 UIAutomation 探索版成功的前置条件。无法证明安全性时，只交付 UIA 能力。

### Phase 10：UiPath 兼容增强（第 28–30 周）

范围：

- 内部 Selector 到 UiPath Selector XML 的映射。
- 网页 Selector XML 导出。
- 在语义可可靠映射时加入桌面 UIA Selector。
- UiPath 风格层级编辑视图。
- XML 与内部层级启停保持一致。
- 研究 XAML schema 并生成最小验证样例。
- 使用指定 UiPath Studio 版本真实验证。

如果 XAML 无法稳定兼容，只交付经过验证的 Selector XML。

### Phase 11：项目管理与 Selector 回归验证（第 31–34 周）

范围：

- `.uiproj` schema 版本和迁移机制。
- 项目创建、打开、保存、另存为和删除。
- 以明确类型保存网页、桌面和表格定位资产。
- Selector 分组、命名、备注和搜索。
- 元素快照和截图。
- 最近项目。
- 批量回归验证和失败原因。
- 对当前环境无法验证的资产显示“未运行”。

项目默认仅本地保存。本阶段不提前加入账户、云同步或协作字段，只保留必要的 schema 版本和扩展边界。

### Phase 12：AI 辅助（第 35–36 周）

范围：

- Selector 层级解释。
- 失败原因总结。
- 稳定候选推荐。
- URL、文本、属性和凭据脱敏。
- 外部模型显式选择。
- 推荐结果的本地 Selector 验证。

AI 不直接执行代码，也不直接修改项目资产。

### Phase 13：企业能力（后续版本）

范围：

- 云同步和版本历史。
- 团队共享、评论和变更记录。
- 项目级和团队级权限。
- 审计日志。
- 带沙箱和 API 版本管理的插件系统。
- 同步冲突解决和项目 schema 升级策略。

企业能力根据真实用户需求启动，不进入 MVP。

## REQUIREMENTS.md 联动修改

正式更新不能只替换路线图。以下位置需要同步：

- 项目概述：从网页 MVP 闭环中移除项目保存。
- 路线原则：明确网页能力稳定优先和资产化后置。
- MVP 必须能力：移除项目保存。
- MVP 暂不承诺能力：加入项目管理并标记为 Phase 11。
- 后置能力阶段引用：
  - 桌面 UIAutomation → Phase 9
  - 冻结捕获 → Phase 9
  - UiPath → Phase 10
  - 项目管理 → Phase 11
  - AI → Phase 12
  - 企业能力 → Phase 13
- 表格需求：拆分已完成的 CSV/JSON/Markdown 与 Phase 7 的 Excel、选择性提取和伪表格。
- Phase 4–13：重写目标、任务和验收标准。
- 里程碑总览：同步阶段名称、周期和主要价值。
- 待确认需求：保留仍影响实现的选择，改写与新顺序冲突的表述。

性能、安全和架构要求中仍有效的未来目标继续保留，不因阶段后移而删除。

## 状态与表达规则

- Phase 0–3 保留原有编号和内容，标记为已完成。
- Phase 4 改为独立的标准 HTML 表格阶段，标记为已完成。
- Phase 5–13 标记为计划中。
- “已完成”只用于仓库中已经实现并验证的范围。
- 已完成范围之外的增强项必须明确归入后续 Phase，不得混写为 Phase 4 成果。
- 周期均为相对项目周，用于表达工作量和依赖，不代表固定发布日期。

## 一致性验收

更新后执行以下检查：

1. 搜索所有 `Phase` 引用，确认旧编号没有残留。
2. 检查每项未完成功能都有且只有一个主要归属阶段。
3. 对照每个阶段的目标、任务、验收标准和里程碑，确认语义一致。
4. 检查 MVP 表格与后续路线图不存在项目保存、桌面、UiPath 等范围冲突。
5. 检查 Phase 4 只包含已经完成的标准 HTML 表格范围。
6. 检查项目管理只出现在 Phase 11，企业同步只出现在 Phase 13。
7. 扫描 `TBD`、`TODO`、旧周期和旧里程碑名称。
